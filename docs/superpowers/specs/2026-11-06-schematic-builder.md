# Rusty schematic construction

The user wants Build Planner to open a native file picker, import a schematic and automatically walk, source inventory blocks and build it. They also want two-corner export from an opened world and a copyable list of every required block/material. Existing autonomy authorizes implementation, owned-fixture testing, publication to GitHub/Modrinth and official Horizon integration without repeat questions. Never modify personal saves or mine/build in Horizon Official.

Implement independently from public format behavior. No reference-mod code, assets or promotional credits enter Rusty. Existing license notices stay intact; new reused dependencies retain required notices. The invoked REA skill routes complete open-source references through ordinary source inspection, without installing REA engines or changing client configuration.

## Chosen approach

Extend the existing Minecraft-style Build Planner, preserving its box preview and one-action placement. Add Load schematic, Clear schematic, Set origin, Rotate, Mirror, Materials/Copy materials, Start construction/Stop, export first/second corners and Save selection buttons with small contextual help. Use native Rust for Horizon, Java host adapters for the existing Fabric/NeoForge editions. Files and automation are transient and scoped to the connection/world/dimension; no saved activation or automatic restart.

Modern named-state formats: gzip/uncompressed `.litematic` versions4–7, Sponge `.schem` versions2/3, vanilla structure `.nbt`. Export portable Sponge v3 `.schem`. Detect contents rather than trusting extensions; reject legacy numeric `.schematic` honestly rather than silently substitute blocks. Bound input:32MiB compressed,64MiB decompressed, depth64,1,048,576 cells,256 per axis, palette65,536. Reject invalid/unknown states, palette indexes, duplicate/conflicting positions, overlap, dimension arithmetic, invalid strings and malformed/truncated/overlong data before activation. File work and native dialogs run off the game thread. Basenames only in notices.

Use named block states and exact registry validation. Air is skipped for construction; building never automatically demolishes existing obstructions. Block entities/entities are not recreated by survival placement: retain an explicit imported-data warning/count and do not claim full content restoration. Export block states only from all settled received cells, with a clear states-only label; never silently turn unknown/unloaded data into air. Two corners define inclusive dimensions and reset across worlds. Save through an OS dialog, preserve existing files unless the chooser explicitly confirms overwrite, use bounded atomic writes.

## Construction contract

Start is explicit, off/unbound by default. Construction and Auto Mine/Area Clear/other automation have exclusive control. Reuse bounded safe-stand/edge facts; move through ordinary walking only, with no flight, packet tricks, reach changes, demolition or unrequested scaffolding. Prefer supported low layers and nearby actions. Search remains bounded and may report inaccessible parts that need manual access; no globally optimal/any-structure promise.

Select correct hotbar material or ordinarily swap from the main inventory, retaining displaced stack identity. Wait for authoritative inventory processing before placing. Vanilla may suppress matching slot updates, so accept either matching incoming source/destination receipts or a correlated ordinary own-player REQUEST_STATS/AwardStats main-thread processing response ordered after the normal swap, followed by exact source/destination snapshot checks. Track every outgoing stats request and incoming response per connection so prior Stats-menu traffic cannot satisfy a new fence. Any contradictory inventory correction rejects the swap. Do not fabricate slot events, alter menu packets/state IDs, use network-thread Ping as a fence, or invoke an item-use action as a supposedly inert probe. Probe only during an active operation and compare all native predicted placement writes against the intended schematic before dispatch; secondary door/bed writes must be inside and planned. Respect reach, aim, support, orientation/half/axis, entity collision, placement rules and server authority. Count only settled received placement acknowledgment. Do not endlessly retry rejected blocks. Final verification must distinguish complete, already matching, obstructed, missing, unsupported and data-detail/manual leftovers.

Stop on manual key/mouse/controller input, menus, focus loss, damage, health below12/20, food below10/20, changed world/dimension/border, hazard/unknown terrain, lost support, missing material, denied/stalled inventory/placement, another owner or30-minute deadline. Never resume automatically. Default safety values and shortcuts remain resettable through the existing controls. Java restricted multiplayer construction retains current-server view+movement+assistance grants; native remains fully client-side and uses received data.

Materials: sorted copyable item quantities plus readable names/IDs and stack totals; use registry block→item mapping, count double slabs twice and coupled upper/head halves once. Show unmappable/manual states explicitly. Also expose block-state totals so no input block is hidden by material normalization. Copy uses the actual OS clipboard. No file chooser or copy action starts construction.
