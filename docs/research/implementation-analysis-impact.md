# Impact: individual public contracts and independent native designs

> Dated reference-mechanism research and design context. Current executable acceptance is recorded only in [Rusty validation](../VALIDATION.md).

The official [feature page](https://impactclient.net/features) was re-fetched on 2026-11-04. Its complete embedded `features` object is byte-semantically identical to the frozen 2026-11-03 object: canonical sorted JSON SHA-256 `4b9460df2a903e6039aa72bb18a5899342d532e0462f46cd4991751197a40c35`. All 117 module-level public descriptions and the complete setting hierarchy were examined; factual setting identifiers remain in [the register](implementation-analysis-register.json). The browser text extractor sees headings only, so the embedded object is the actual public documentation evidence. No Impact internal source, executable behavior, modes omitted from that page, or current-version compatibility is established here.

Each following row is an original implementation proposal and discriminating test for that particular documented feature. It is **not** a claim that the proposed algorithm is Impact's algorithm. The open-source behavior comparisons in the other implementation-analysis documents provide independently inspectable examples where appropriate. Unclear marketing descriptions stay unclear; no invented implementation is credited. Empty documented settings do not mean a feature has no settings.
