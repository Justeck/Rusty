# Player, inventory, mining and world automation analysis

> Dated reference-mechanism research and design context. Current executable acceptance is recorded only in [Rusty validation](../VALIDATION.md).

Read 2026-11-04 against Meteor `e3a2e77967629d216e127b5ceecf71fb15f9d2e5`. All constructor-through-end module methods in `systems/modules/player` were read, alongside all `world` module methods **except HighwayBuilder**, where activation, cancellation, main tick/state selection, centering, relevel and container-restock paths were examined. HighwayBuilder's full geometry providers and every state remain unaudited. Config declarations are structurally inventoried; indirect helper/mixin behavior is limited to what is named below. No Java client or native game was run for this analysis.

Complete per-file pinned source URLs and setting identifiers/types are in [the register](implementation-analysis-register.json). Primary directories: [player](https://github.com/MeteorDevelopment/meteor-client/tree/e3a2e77967629d216e127b5ceecf71fb15f9d2e5/src/main/java/meteordevelopment/meteorclient/systems/modules/player), [world](https://github.com/MeteorDevelopment/meteor-client/tree/e3a2e77967629d216e127b5ceecf71fb15f9d2e5/src/main/java/meteordevelopment/meteorclient/systems/modules/world).

## Native adaptation order

The code review supports several practical steps beyond a refusal/backlog label: protected-target input filtering; normal hotbar item shortcuts; hunger/repair hysteresis; received fluid/storage/light indices; finite cell-selection previews; typed menu transactions; and bounded normal break/place tasks. These are reusable across many names without claiming mode parity. AutoBrewer/Smelter/Trader require menu-specific logic, while mining/farming/highway tasks require resource and geometry revision state. One generic “automation” toggle would conceal those differences.

A worker should compute plans from immutable snapshots; it must not mutate live inventory/player objects or retain references across world generations. The main update path revalidates a plan and executes a single normal action. All pending callbacks and timers need a finite timeout and session generation. Account/world observations and coordinate exports stay separate from portable feature profiles. No reference's successful helper return, local prediction, or attempt counter establishes server acceptance or item safety.
