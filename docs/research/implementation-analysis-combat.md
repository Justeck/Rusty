# Combat behavior methods: distinct mechanisms and native acceptance

> Dated reference-mechanism research and design context. Current executable acceptance is recorded only in [Rusty validation](../VALIDATION.md).

Review date 2026-11-04, Meteor `e3a2e77967629d216e127b5ceecf71fb15f9d2e5`. Constructor-through-end behavior methods were read for all 30 source classes in the pinned [combat directory](https://github.com/MeteorDevelopment/meteor-client/tree/e3a2e77967629d216e127b5ceecf71fb15f9d2e5/src/main/java/meteordevelopment/meteorclient/systems/modules/combat). AutoArmor's earlier methods and KillAura's remaining weapon predicates were read separately. This establishes source-method analysis, not full transitive mixin coverage, all configuration defaults or execution results. The register preserves directly declared setting names/types and complete per-class URLs. `AntiAnchor` exists in source but is not registered by default; do not count it as normally available.

## Shared mechanisms that matter

`TargetUtils.getList` collects all accepted received entities and fake training entities, sorts the whole list, then truncates it. A native nearest/best-one query can maintain a running best; top-k queries can use a fixed-cap heap and cheap filters before expensive line-of-sight/damage rays. “Nearest player” must not accidentally include the camera or synthetic training entity. Revalidate friends/permissions before dispatch because relationships or entity IDs can change. Stable target identity includes world generation, not just the numeric entity ID.

`DamageUtils` estimates explosion exposure by ray sampling across a target bounding box, combines distance and exposure, then applies difficulty, armor/toughness, resistance and enchantment reductions. Its default exposure factory ignores blocks below a blast-resistance threshold, and hypothetical crystal/anchor positions can override a block state. Movement prediction shifts the position and box by one received velocity step. These are deliberate approximations, **not an authoritative damage oracle**: custom game rules, missing terrain/equipment, immunity frames and server plugins can invalidate them. A native threat preview should reuse the host's own damage rules where possible, expose uncertainty and bound rays/targets per tick. Never use unknown exposure as zero self damage. The inspected general explosion expression has a fixed strength factor in its final calculation even when called with different distance scales; do not assume all explosion types are exactly modeled.

Melee scoring copies an attack-damage attribute, replaces main-hand modifiers, adds target-tag-specific enchantments, current charge, mace bonuses and critical conditions, then estimates reductions. This is richer than comparing sword-name tiers, but maximizing one immediate damage estimate is a different objective from DPS, shield breaking, durability or looting. The native UI should make the objective explicit and keep a stable selected-slot tie. Source: [DamageUtils](https://github.com/MeteorDevelopment/meteor-client/blob/e3a2e77967629d216e127b5ceecf71fb15f9d2e5/src/main/java/meteordevelopment/meteorclient/utils/entity/DamageUtils.java), [TargetUtils](https://github.com/MeteorDevelopment/meteor-client/blob/e3a2e77967629d216e127b5ceecf71fb15f9d2e5/src/main/java/meteordevelopment/meteorclient/utils/entity/TargetUtils.java).

## Performance and reliability consequences

Explosion candidates × targets × exposure rays can dominate a tick. Use a fixed candidate/ray budget, cheap reach and permission filters first, cached block-shape/armor snapshots, and a generation/revision key. Carry incomplete computation to later ticks rather than doing an unlimited synchronous scan. The UI must display pending/partial estimates. A user's move, world change or block update can invalidate a candidate even if the damage calculation just completed.

Source algorithms often mark attempted blocks/entities removed or complete to avoid repeatedly selecting them. A native implementation should keep `requested`, `predicted`, `received` and `rejected/expired` states distinct. That improves diagnostics and prevents unconfirmed local state from becoming permanent truth. No source performance or server success rate was benchmarked in this review.
