# Navigation helper follow-up: search is distinct from movement authority

> Dated reference-mechanism research and design context. Current executable acceptance is recorded only in [Rusty validation](../VALIDATION.md).

Complete additional Wurst reads on 2026-11-04 at `4e4a957e87ffd79d120835fb47fa9c139006abb8`: PathFinder, PathQueue, PathPos, PlayerAbilities, PathProcessor, WalkPathProcessor and FlyPathProcessor. Evidence: [pinned AI directory](https://github.com/Wurst-Imperium/Wurst7/tree/4e4a957e87ffd79d120835fb47fa9c139006abb8/src/main/java/net/wurstclient/ai). These close the base search/execution delegation from Path and Goto commands; subclass mining/follow-specific pathfinders and collision/render helpers remain separate. No reference implementation was copied.

The base search is incremental weighted A*: an ordered queue holds position/priority pairs, cost/predecessor maps store improvements, and each think call polls up to1024entries by default. Budget defaults200think batches, with a horizontal expansion boundary256cells from start. Nodes include a jumping flag in equality/hash. Improved nodes are appended as new queue entries; stale duplicate priorities are not removed or filtered explicitly. This spends extra queue/poll budget but is not a decrease-key implementation. There is no separate hard cap on queue allocation.

Neighbor generation allows cardinal and diagonal horizontal moves, separate up/down nodes, and climbing/swimming/flying conditions. Diagonals require both side cells passable without mining, reducing corner cutting. Feet/head block rules use motion-blocking tags and special cases for signs, ladders, tripwire, pressure plates, fluids, fire, fences and walls. Unknown chunk cells are rejected by the through-cell predicate. These tag/cell approximations are not full swept player-shape collision for slabs, stairs, crawl poses or custom geometry. Base `isMineable` is false; subclass mining is a separate capability.

Falls inspect preceding vertical nodes up to an allowance and special-case water, webs, ladders, slime and assumed immunity. PlayerAbilities treats several **enabled client modules** as capabilities: Flight implies flying; NoFall implies fall immunity; Jesus enables liquid support; Spider enables climbing. Enabling such a local module does not establish actual remote server permission or fall safety. The copy constructor carries think speed/time but leaves falling/diving flags at default, so a replan copied from cautious settings can restore permissive flags.

Transition cost averages source/destination cell penalties: water approximately1.316, lava4.540, soul sand2.5 and each mineable feet/head cell factor2; diagonal multiplies bysqrt2. The heuristic is Manhattan including vertical, adjusted for horizontal diagonals, and multiplied by1.001. That inflation deliberately forfeits an admissible shortest-path guarantee. Current-position goal detection stops as soon as popped. Formatting a failed search chooses a reachable recorded node with better heuristic, preferring standing/flying conditions; this produces a partial frontier path, not arrival at the original goal. Path validity rechecks ability snapshot and every remaining neighbor transition.

Walk execution converts current body to a block coordinate, advances/skips indices if already farther down the list, faces the next node and drives forward/jump/sneak according to height, ladder and liquid rules. It locks six movement controls and clears sprint rather than leasing only its own requests. It forcibly disables local flight. Fly execution has different tight waypoint boxes, velocity damping and axis control; noncreative mode can directly snap local position near a node based on module speed. This is not ordinary server-authorized navigation. Both track off-path ticks but the top-level caller must decide recovery/cancellation. Releasing resets key states through a helper whose physical-input behavior is a further boundary.

The native delivery therefore reuses Horizon's existing bounded loaded-terrain A* and ordinary task execution for **WaypointWalk**, with verified server/local-save/dimension target, finite coordinates, explicit task owner, manual cancellation and progress/timeout recovery. The earlier SDK review found a30000expanded-node budget, cardinal transitions with level/+1/-1/-2/-3height choices, lava/unknown exclusion, water penalty and partial frontier handling. Its heuristic is also not a proven optimality guarantee for combined horizontal/vertical moves. Source/native acceptance tests must assess actual arrival and safe control release rather than just a returned path.

Required discriminating navigation tests: diagonal corner pinch, top/bottom slabs and stairs, custom collision shapes, low ceiling, fall3/4boundary, water exit, lava beside safe path, unloaded frontier, target above unreachable structure, unreachable goal yielding partial route, many stale queue entries, changed ability/rules, replan preserving fall/diving policy, manual key held during cancellation, world/dimension switch, target movement and another task replacing this owner. Route visualizations should explicitly show partial/unknown endpoints. Future legitimate extensions can add shape-aware transitions and incremental dependency planners; they must not assume local movement toggles grant remote capabilities.
